# Working on dfx

This repository has separate Claude and Codex entrypoints. Preserve the Claude
implementation in `skills/dfx`, `agents`, and `.claude-plugin` when changing Codex.
Codex sources live in `codex/skills/dfx`; do not translate Claude tool names or
model aliases literally. Read the relevant entrypoint before changing behavior.

The Codex skill uses the host's native subagent tools, not a nested CLI runtime.
Keep its entrypoint short; runtime-specific delegation, model routing and
verification details belong in its linked references. No mandatory agent count
or fixed review pipeline for small tasks.

Validate Python helpers with `python3 -m unittest discover -s scripts -p 'test_*.py'`.
Behavioral evaluations belong in disposable directories, never the user's
application repository. Run independent subagent evaluations when making
substantial orchestration changes; provide realistic tasks rather than expected
answers. Preserve evidence and report limitations rather than claiming benchmark
improvements from smoke tests.

The installer must preserve unrelated user skills and configuration. Do not
commit run artifacts, credentials, or generated bytecode.
