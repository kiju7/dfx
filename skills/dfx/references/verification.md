# 증거, 리뷰, 복구, 인계

## 완료 기준

편집 전에 성공을 확정할 관찰 가능한 동작을 짧게 정합니다.

- 버그: 가능하면 재현하고, 수정과 회귀 경로를 검증
- API: 바뀐 성공·실패 계약과 영향받는 소비자를 실행
- UI: 도구가 허용하면 렌더와 관련 상호작용 확인
- 리팩터: 기존 검사와 표적 보완으로 동작 보존 확인

통과한 테스트는 실행한 범위만 뒷받침합니다. 기준을 낮추거나, 실패 테스트를 지우거나, 실행하지 않은 검사를 통과로 적지 않습니다. 기존 환경 실패와 이번 변경의 실패를 분리합니다. **완료 선언 전에 검증 명령을 실제로 실행한 결과가 있어야 합니다.**

## 리뷰: 기본은 끝에 한 번

- **기본:** 모든 편집과 검사가 끝난 뒤, 전체 diff 에 대해 새 `dfx:reviewer` 1명이 한 번 봅니다. 작업마다 리뷰하지 않습니다.
- **작업 단위 리뷰:** 뒤 작업이 그 결과 위에 쌓이는 공유 계약·스키마, 또는 되돌리기 어려운 조각에만 씁니다.
- **생략:** 작고 명확한 변경, 사용자가 "리뷰 없이" 라고 한 경우. 자기 검증은 합니다.

리뷰어에게는 사용자 의도, 기준 리비전 또는 diff, 관련 파일, 실행한 검사와 결과, 렌즈를 주되 구현자의 결론은 주지 않습니다. 보안·성능·UX 렌즈는 해당 위험이 있을 때만 추가합니다. finding 에는 영향과 코드·재현 증거가 필요하며, 추측성 스타일 선호는 고치지 않습니다.

## 범위 한정된 복구

정당한 finding 을 고치고 영향받은 동작만 다시 확인합니다. 이후 변경이 무효화하지 않은 통과 증거는 재사용합니다.

**정지 정책:** 같은 문제에 새 증거 없이 수리 2회 → 원인·범위 재평가. 다른 계획 1회 또는 더 강한 모델로 인계 1회까지 허용하고, 그래도 진전이 없으면 차단 요인을 기록하고 인계합니다. 진전은 재현된 원인, 고친 계약, 해결된 finding, 새로 통과한 검사입니다. 사용자의 예산·한도가 우선합니다. 끝없는 QC 루프를 돌리지 않습니다.

## Workflow 로 수렴 (조건부)

독립 렌즈 3개 이상을 병렬로 돌리고 finding 을 적대적으로 검증해야 하거나, 발견→수정→재검증이 2라운드 이상 예상되거나, 변경이 조정자 문맥을 넘을 만큼 크면 `Workflow` 를 씁니다(`/dfx` 가 옵트인). `workflow-authoring` 을 먼저 로드하고, 출력은 `schema` 로 강제하며, 렌즈별 리뷰는 `pipeline()` 으로 흘립니다. 규모는 세션이 알려주는 지침(예: `medium` 이면 10 에이전트 미만)을 따릅니다. `Workflow` 가 없으면 한 메시지의 병렬 `Agent` 호출로 대신하고 라운드는 정지 정책으로 묶습니다.

## 실행 기록 (위임·다단계만)

대상 프로젝트의 `_workspace/dfx/<run-id>/`(UTC 타임스탬프 + 난수, 공유 `/tmp` 경로 금지)에 둡니다. 커밋하지 않고, 필요하면 `.git/info/exclude` 에 추가합니다. 조정자만 씁니다. 비밀·자격 증명은 저장하지 않습니다. 사소한 편집에는 만들지 않습니다.

```json
{
  "status": "running",
  "request": "사용자가 요청한 결과",
  "requirements": [{"id": "R1", "criterion": "관찰 가능한 동작", "evidence": []}],
  "tasks": [{"id": "T1", "goal": "", "depends_on": [], "write_scope": [],
             "status": "pending", "agent_id": null, "requested_model": null,
             "confirmed_model": null, "routing_reason": "", "repair_attempts": 0, "evidence": []}],
  "decisions": [], "blockers": [],
  "usage": {"input_tokens": null, "output_tokens": null, "source": null}
}
```

- 작업 상태: `pending | running | verified | blocked`. 실행 상태: `running | ready_for_review | blocked | cancelled`. 필수 작업·검사가 충족돼야 `ready_for_review` 입니다.
- 형제 임시 파일에 쓰고 원자적으로 교체합니다. 재개 시 현재 diff 와 기록된 증거를 먼저 보고 결과를 재사용합니다. 문맥 압축만으로 완료 작업을 다시 하지 않습니다.
- 사용량은 런타임이 준 값만 출처와 함께 적고(예: Agent 완료 알림 → `agent-notification`), 없으면 `null` 입니다. 부모·자식 합계를 겹쳐 더하지 않습니다. `confirmed_model` 은 런타임 메타데이터가 있을 때만 채웁니다.

인계 시 짧은 `report.md`: 요구사항별 결과와 증거, 실질적 변경, 실행하지 못한 검사·차단 요인, 모델 선택. 사용자 언어로 씁니다. publish·merge·deploy 는 사용자의 실제 허가를 따릅니다.
