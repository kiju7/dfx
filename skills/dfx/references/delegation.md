# 네이티브 위임과 작업 계약

## 호스트 어댑터 (Claude Code)

이 세션에 실제로 노출된 도구 스키마를 씁니다. 가정한 SDK 가 아닙니다.

| 표면 | 위임 | 후속·결과 |
|---|---|---|
| `Agent` 도구 | `subagent_type`, `prompt`, `description`, `model`, 선택적 `isolation: "worktree"` | 백그라운드 완료 알림, `SendMessage` 로 같은 에이전트 이어가기 |
| `Workflow` 도구 | 스크립트가 `agent()`·`parallel()`·`pipeline()` 으로 팬아웃과 수렴 루프를 결정적으로 소유 | 완료 알림, `/workflows` 진행 상황. 작성 전 `workflow-authoring` 스킬을 로드 |
| 위임 도구 없음 | 요청을 달성할 수 있으면 로컬로 수행하고, 위임이 불가하다고 밝힘 | — |

**병렬은 한 어시스턴트 메시지에 Agent 호출 N개** 입니다. 메시지를 나누면 순차입니다. 결과를 예측하거나 지어내지 않습니다. 알림이 올 때까지 다른 독립 작업을 합니다.

dfx 가 제공하는 에이전트:

| `subagent_type` | 용도 | 기본 |
|---|---|---|
| `dfx:worker` | build/explore. 자기완결 브리프 하나를 소유하고 구현·검증·구조화 보고. 재위임 없음 | 전체 도구, `opus` (호출별 `model` 로 덮어씀) |
| `dfx:reviewer` | 독립 리뷰. 읽기 전용, 실행 증거가 있는 finding 만 반환 | `Read/Grep/Glob/Bash`, `opus` |

플러그인이 아닌 개인 설치(`~/.claude/agents/`)면 접두사 없이 `worker`/`reviewer` 입니다. 둘 다 없으면 `general-purpose` 에 같은 브리프를 주고, 읽기 전용 제약은 프롬프트로 명시합니다. 값싼 읽기 전용 탐색은 내장 `Explore` 로 충분합니다.

`subagent_type: "fork"` 는 대화 전체를 상속합니다. 조정자 문맥이 그대로 필요한 부수 작업에만 쓰고, 다른 모델이 필요하면 자기완결 브리프로 새 에이전트를 씁니다. 사용자·프로젝트 제약(CLAUDE.md, 권한)은 새 문맥에서도 살아 있어야 하므로 브리프에 적용되는 것을 적습니다.

**교차 벤더 리뷰(조건부):** 에이전트 목록에 `codex:codex-rescue` 가 있으면, 영향이 큰 변경에 한해 독립 리뷰어 1명으로 씁니다. 같은 계열 모델이 못 보는 사각지대를 다른 계열이 잡습니다. 없으면 생략하고 보고서에 적지 않습니다.

호스트의 동시 실행·중첩 한도와 실제 빌드·테스트 부하를 함께 고려합니다. 이전 문맥이 유용하면 쉬고 있는 에이전트를 이어 쓰고, 독립 리뷰나 무관한 작업은 새로 위임합니다.

생성·재개가 한도 오류로 거부되면 노출된 상태 정보부터 확인합니다. thread 한도를 동시 실행 슬롯 부족으로 단정하지 말고, 원인이 불명이면 그대로 보고합니다. 관련 실행의 완료를 기다리거나, 호스트가 정리 기능을 제공할 때만 불필요한 완료 에이전트를 정리합니다. 중단을 삭제로 간주하지 않습니다. 관련 상태 변화나 사용 가능한 대안이 있을 때 한 번 재시도하고, 계속 거부되면 가능한 작업은 직접 수행하되 독립 리뷰 누락을 밝힙니다. 시도한 위임·설정과 실제 실행 결과를 구분하고, 새 근거 없이 생성·재개를 반복하지 않습니다.

`Task` 같은 옛 도구명을 부르거나, 도구·역할을 지어내거나, 위임을 흉내 내려고 `claude -p` 같은 중첩 CLI 를 띄우지 않습니다. 전문 분야 Markdown 파일 목록이 에이전트를 등록하지 않습니다. 호스트가 실제로 그 역할을 노출하지 않으면 전문성은 브리프에 담습니다.

## 분할

직무명이 아니라 **결합된 동작과 코드 의존성**으로 나눕니다. 병렬 소비자가 구현하기 전에 공유 API·스키마 계약을 확정합니다. 파일이 달라도 의존성·빌드 산출물 충돌은 납니다.

**같은 작업 트리에 동시 쓰기 금지.** 실제 사고: 디렉토리가 서로 다른 포맷 핸들러 6개를 "병렬 안전" 으로 보고 동시에 돌렸다가 교차 패키지 테스트 실패와 lost-update 가 나서 수동 복구했습니다. 원인은 공유 git index, 공유 빌드 산출물(`target/`, `dist/`, `node_modules/`), 미완성 코드가 다른 에이전트의 컴파일을 깨는 교차 심볼 해석, 공유 설정 파일(`package.json`, `pom.xml`)입니다. 병렬 쓰기는 다음 중 하나로만 합니다.

- `isolation: "worktree"` 로 각 worker 를 격리하고 조정자가 순서대로 통합
- 소유 파일을 분리하되 **빌드·테스트는 한 번에 하나만** 돌게 브리프에 명시하고 통합을 직렬화. 이 방식에서는 worker 가 자기 파일에 한정된 검사만 돌리고, 여러 소유자의 파일을 함께 import 하는 **공유 테스트 스위트·전체 빌드는 조정자가 통합 후 1회** 실행합니다. 수정이 필요하면 해당 파일의 기존 소유자에게 차이만 돌려줍니다.

읽기 전용 리뷰마다 worktree 를 만들지는 않습니다. 비슷한 N개 작업(핸들러 N개, CRUD 화면 N개)은 첫 번째를 기준 구현으로 삼아 후속 브리프에 그 결과와 패턴을 넘깁니다.

작업에는 담당자에게 도움이 되는 필드만 넣습니다.

```text
Goal: 사용자에게 보이는 결과 또는 구체적 질문
Context: 관련 요구사항, 결정, 파일/심볼 포인터, 형제 작업의 결과
Write scope: 허용된 파일/모듈, 보존해야 할 기존 사용자 변경
Inputs/dependencies: 준비된 것과 기다려야 할 것
Done when: 관찰 가능한 완료 기준과 관련 검사
Return: 변경/발견, 증거, 미해결 항목, 제안 인계
Constraints: 적용되는 지침과 권한, 재위임 금지, 동시 빌드 금지 여부
```

담당자는 코드를 읽은 뒤 구현을 다듬을 수 있습니다. 목표·계약·소유권을 바꿔야 하면 증거를 조정자에게 보고합니다. 현재 산출물이 이미 뒷받침하는 탐색을 반복하지 않습니다.

## 역할은 작업 모드

- **Explore:** 경로와 증거로 한정된 불확실성에 답합니다. 읽기 전용.
- **Build:** 응집된 동작 하나를 집중 검증까지 소유합니다.
- **Review:** 요구사항·diff·관련 코드를 독립적으로 검사하고 근거 있는 finding 을 돌려줍니다. 명시적으로 맡기지 않는 한 구현 편집 없음.
- **Integrate:** 완료된 작업을 조율하고 공유 동작을 검증합니다. 보통 조정자가 하며 별도 상설 에이전트가 아닙니다.

도메인 지식(데이터베이스, UI, 보안, 성능)은 해당 브리프에 담습니다. [domains.md](domains.md) 에서 검토 중인 위험에 해당하는 절만 로드합니다. 가능한 모든 역할마다 에이전트를 만들거나 파일마다 계획·리뷰 체인을 반복하지 않습니다.
