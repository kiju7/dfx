# 모델 선택

측정된 성능 보장이 아니라 출발 정책입니다. 이 세션의 `Agent` 도구가 받는 `model` 값(예: `haiku | sonnet | opus | fable`)을 먼저 확인하고, 매 작업마다 모델 문서를 찾아보거나 선호 모델을 강제하려고 사용자 설정을 고치지 않습니다.

| 작업 증거 | 우선 모델 |
|---|---|
| 한정된 추출·조회(파일 찾기, 값 모으기) | `haiku` |
| 기계적으로 검사 가능한 편집, 기존 패턴을 따르는 범위 명확한 구현·테스트 | `sonnet` |
| 모호한 계획, 결합된 구현, 원인 불명 결함, 독립 정확성 리뷰 | `opus` |
| `opus` 가 같은 작업에서 막힌 증거가 있거나, 처음부터 최상위 추론이 필요한 영향 큰 설계·교차 시스템 결함 | `fable` |

등급마다 세대가 다를 수 있습니다. 세션이 알려주는 모델 목록을 보고, 한 등급이 한 세대 뒤처져 있으면 판단이 섞인 작업에는 그 등급을 쓰지 않습니다.

Claude Code 의 `Agent` 도구에는 별도 effort 파라미터가 없습니다. 난도는 모델 선택과 브리프의 범위·완료 기준으로 조절합니다. 역할명과 모델을 동일시하지 않습니다. 작은 계획은 조정자가 직접 세우고, 조회는 `haiku`, 기계적 구현은 `sonnet` 으로, 미묘한 구현은 처음부터 `fable` 로 시작할 수 있습니다. 조정자(부모) 모델은 호스트가 이미 정했으며, 지시문이나 설정으로 바꿨다고 주장하지 않습니다.

## 조정자가 이미 강한 모델일 때

조정자가 `opus` 이상이면, 같은 등급 worker 에게 결합된 작업을 넘겨도 능력 이득은 없고 문맥 전달 비용과 오해 위험만 생깁니다. 이때 위임은 다음 셋 중 하나가 있을 때만 합니다.

- **병렬:** 서로 독립인 단위가 둘 이상이라 경과 시간이 줄어듦
- **문맥 보호:** 대량 읽기·긴 로그·반복 검사가 조정자 문맥을 채울 것임(`Explore`, 또는 대화 문맥이 필요하면 `fork`)
- **독립성:** 구현자 결론에 물들지 않은 리뷰가 필요함

셋 다 아니면 조정자가 직접 합니다. 조정자 토큰은 판단과 결합된 편집에 쓰고, 요약·증거·결정만 남깁니다.

위임마다 모델과 근거를 한 줄로 기록합니다. 목표는 재작업·경과 시간·사람 검토 노력을 포함한 성공적 완료이지, 개별 호출의 최저 비용이 아닙니다. 단순 도구 실행 하나에 에이전트를 붙일 필요는 거의 없습니다. 토큰 단가가 높다는 이유만으로 강한 모델이 나쁜 선택이 되지는 않습니다.

## 증거에 따라 조정

- 사실이 부족: 추론을 늘리지 말고 특정 코드·로그·계약을 가져옵니다.
- 범위·의존성이 틀림: 작업 계약과 소유권을 먼저 고칩니다.
- 범위 한정된 코딩 실수: 기존 담당자에게 차이만 돌려줍니다.
- 반복되는 추론 실패: 더 강한 모델로 새 에이전트에 인계합니다. 실패한 접근을 짧게 넘겨 후임이 반복하지 않게 합니다.
- 모델 미지원(예: 다른 빌드에서 `fable` 거부): 사용자가 자동 선택을 허용했다면 목록에 있는 적합한 대안(`opus`)을 쓰고 대체 사실을 기록합니다. 비싼 부모 모델을 조용히 물려받고 요청한 싼 모델이 돌았다고 보고하지 않습니다.
- 사용자가 모델을 지정: 대체하지 않습니다. 불가한 능력을 설명하고 가능한 독립 작업을 계속합니다.

변하지 않은 같은 작업에 대한 증거 기반 승급은 1회를 넘기지 않습니다. 그 뒤에는 계획을 재평가하거나 구체적 차단 요인을 보고합니다. 모든 모델 등급을 순회하지 않습니다. 실행 중인 에이전트의 모델은 바꿀 수 없으므로 선택한 모델로 새 에이전트에 인계합니다.

`fork` 는 `model` 오버라이드를 무시합니다. 요청한 모델과 런타임이 확인한 모델을 분리해 기록하고, 메타데이터가 없으면 확인값은 `null` 입니다. 요청 수락이 서빙 모델의 증거는 아닙니다.
