# 모델 선택

측정된 성능 보장이 아니라 출발 정책입니다. 이 세션의 `Agent` 도구가 받는 `model` 값(예: `haiku | sonnet | opus | fable`)을 먼저 확인하고, 매 작업마다 모델 문서를 찾아보거나 선호 모델을 강제하려고 사용자 설정을 고치지 않습니다.

| 작업 증거 | 우선 모델 |
|---|---|
| 한정된 추출·조회, 기계적으로 검사 가능한 편집 | `haiku` (규모가 있으면 `sonnet`) |
| 기존 패턴을 따르는 범위 명확한 구현·테스트 | `sonnet` |
| 모호한 계획, 결합된 변경, 독립 정확성 리뷰 | `opus` |
| 난도 높은 구조, 미묘한 교차 시스템 결함, 영향 큰 판단 | `fable` |

Claude Code 의 `Agent` 도구에는 별도 effort 파라미터가 없습니다. 난도는 모델 선택과 브리프의 범위·완료 기준으로 조절합니다. 역할명과 모델을 동일시하지 않습니다. 작은 계획은 조정자가 직접 세우고, 기계적 구현은 `haiku`/`sonnet` 으로, 미묘한 구현은 처음부터 `fable` 로 시작할 수 있습니다. 조정자(부모) 모델은 호스트가 이미 정했으며, 지시문이나 설정으로 바꿨다고 주장하지 않습니다.

**조정자 토큰은 판단에만 씁니다.** 대량 읽기, 긴 실행 로그, 반복 검사는 worker 에게 보내고 조정자는 요약·증거·결정만 다룹니다.

위임마다 모델과 근거를 한 줄로 기록합니다. 목표는 재작업·경과 시간·사람 검토 노력을 포함한 성공적 완료이지, 개별 호출의 최저 비용이 아닙니다. 단순 도구 실행 하나에 에이전트를 붙일 필요는 거의 없습니다. 토큰 단가가 높다는 이유만으로 강한 모델이 나쁜 선택이 되지는 않습니다.

## 증거에 따라 조정

- 사실이 부족: 추론을 늘리지 말고 특정 코드·로그·계약을 가져옵니다.
- 범위·의존성이 틀림: 작업 계약과 소유권을 먼저 고칩니다.
- 범위 한정된 코딩 실수: 기존 담당자에게 차이만 돌려줍니다.
- 반복되는 추론 실패: 더 강한 모델로 새 에이전트에 인계합니다. 실패한 접근을 짧게 넘겨 후임이 반복하지 않게 합니다.
- 모델 미지원(예: 다른 빌드에서 `fable` 거부): 사용자가 자동 선택을 허용했다면 목록에 있는 적합한 대안(`opus`)을 쓰고 대체 사실을 기록합니다. 비싼 부모 모델을 조용히 물려받고 요청한 싼 모델이 돌았다고 보고하지 않습니다.
- 사용자가 모델을 지정: 대체하지 않습니다. 불가한 능력을 설명하고 가능한 독립 작업을 계속합니다.

변하지 않은 같은 작업에 대한 증거 기반 승급은 1회를 넘기지 않습니다. 그 뒤에는 계획을 재평가하거나 구체적 차단 요인을 보고합니다. 모든 모델 등급을 순회하지 않습니다. 실행 중인 에이전트의 모델은 바꿀 수 없으므로 선택한 모델로 새 에이전트에 인계합니다.

`subagent_type: "fork"` 는 부모 모델을 상속하고 `model` 오버라이드를 무시합니다. 다른 모델이 필요하면 자기완결적 브리프로 새 문맥을 씁니다. 요청한 설정과 런타임이 확인한 설정을 분리해 기록합니다. Agent 결과에 모델 메타데이터가 없으면 확인값은 `null` 로 둡니다. 요청이 수락됐다는 것이 어떤 백엔드가 서빙했는지의 증거는 아닙니다.

## 정책 개선

같은 기준 리비전에서 대표 작업(작은 편집, 일반 기능, 결합 변경, 원인 불명 결함, 영향 큰 변경)을 단일 에이전트 기준선과 적응형 위임으로 비교합니다. 요구사항 완료율, 회귀, 재시도, 경과 시간, 사람의 수정, 확인 가능한 토큰 사용량을 추적합니다. 작업과 평가 환경을 보존합니다. 모델의 자기 평가만으로 최적화하거나 스모크 1회로 절감을 주장하지 않습니다. API 달러 추정과 구독 쿼터 소비는 서로 바꿔 쓸 수 없습니다.
